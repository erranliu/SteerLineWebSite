# SteerLine 官网架构方案

本文记录目前确认的网站定位、技术栈、页面结构和双语内容发布流程，作为后续设计与开发的依据。页面路径和目录为建议结构，实施时可根据框架约束调整，但应保留本文确定的内容边界和语言规则。

实际发布按[官网部署手册](./deployment.md)执行，包含中英文同步、Cloudflare Pages 上传、域名验证和回滚。

## 1. 网站定位

官网承担三个职责：

1. **产品入口**：介绍 SteerLine 的定位、核心理念、工作方式和项目状态。
2. **知识传播**：发布面向严肃 AI 软件工程的通用开发教程。
3. **产品学习**：提供 SteerLine 使用教程，当前功能和配置细节链接至项目仓库。

网站面向希望使用 AI 开发真实软件的个人开发者、技术负责人和团队，既帮助初次接触者理解方法，也支持使用者在实际项目中查找操作和参考信息。

SteerLine 当前尚未发布。官网应区分已实现并验证的能力与计划中的能力，并随产品进展更新项目状态。

## 2. 信息架构

### 2.1 主导航

| 英文 | 中文 | 用途 |
| --- | --- | --- |
| Product | 产品 | 产品定位、理念、工作方式和状态 |
| Learn AI Development | 学习 AI 开发 | 不依赖特定产品的 AI 软件工程方法 |
| Learn SteerLine | 学习 SteerLine | SteerLine 的理念、操作和实践案例 |
| About | 关于 | 作者介绍、教程初衷、独立工具和免费长期更新承诺 |

Logo 返回当前语言首页。导航右侧提供站内搜索、中英文切换和 GitHub 入口。项目更新和关于也放在页脚，首页项目状态区和产品页保留项目进展入口。“文档”栏目已整体移除，不保留独立页面或导航入口。

### 2.1.1 学习页面视觉与导航（2026-10-27 确认）

- 首页、学习入口和文章页共用品牌、主导航、米白背景、深绿色文字与浅绿色区块。
- 学习 AI 开发入口采用全宽自定义 Astro 页面，不显示文档侧栏；以适度留白的标题区和“从第一篇开始”入口引导阅读。
- 课程保留入门阶段、进阶阶段、AI 和认知科学，以及专栏文章四个栏目，以编号、简介和文章列表组织；进阶阶段和 AI 和认知科学标注“待更新”。
- 文章页继续使用 Starlight 的阅读与本文目录能力，左侧只显示当前内容区的目录，并展开当前分组；底部提供前后篇和返回学习首页，AI 开发课程文章另有双语课程讨论区入口。
- 移动端主导航可横向滚动，课程目录和本文目录收起；语言切换保留对应文章关系。
- 现有路由和 content ID 保持稳定。本轮先提供本地预览，不发布生产站点。

### 2.2 页面结构

专栏文章归属于“学习 AI 开发”，入口为 `/<locale>/ai-engineering/#articles`，不设独立主导航或页脚栏目。保留已有的 `/<locale>/articles/` 路由以兼容已发布链接，文章存放在 `src/content/docs/<locale>/articles/`。目录按展示顺序排列，不显示课程编号；文章页提供返回专栏的入口，不提供上一篇、下一篇导航。正文未完成时沿用现有的标题占位与待整理提示。

中英文使用相同的信息架构和内容分类。下方路径省略语言前缀：

│   ├── overview/                产品概览

具体文章随产品成熟度逐步增加，第一版不必创建空页面。

### 2.3 内容边界

| 内容区 | 回答的问题 | 内容特征 |
| --- | --- | --- |
| 学习 AI 开发 | 为什么这样做？通用方法是什么？ | 以软件工程问题和方法为中心，可独立于 SteerLine 阅读 |
| 学习 SteerLine | 如何用 SteerLine 实践？产品为什么这样设计？ | 解释产品理念、完整操作流程和实践案例 |

例如，学习 AI 开发解释为什么使用 worktree 隔离并行任务；学习 SteerLine 解释如何在 SteerLine 工作流中处理相关任务。具体配置和行为链接至项目仓库，避免重复维护同一项精确配置或命令说明。

## 3. 首页结构

2026-11-03 按主仓库最新 README 调整中文版首页。SteerLine 定义 AI Workshop：以多 Agent 编排为基础，将开发方法与配套工具融入项目流程。本轮中文先发布，英文首页保留 2026-11-01 的 Roadmap 驱动版本，待后续同步。

1. **AI Workshop 与产品价值**：首屏使用“你把握产品方向，SteerLine 组织开发”，简述类别定义，以用户、主 Agent、多个执行 Agent 的关系图说明目标工作方式。主入口定位本页的开发方式对比，次入口进入 GitHub，标明尚未发布。
2. **为什么注入流程**：说明多 Agent 执行能力增长带来的协调负担，以及人的注意力瓶颈；用明确依据、注入执行要求、核验结果三步说明流程如何落实。
3. **开发方式的变化**：对比人直接组织 Agent 与 SteerLine 目标流程下的规划、协作、验收和人的投入，链接产品页完整流程。
4. **当前阶段与继续了解**：简述已有基础，明确主 Agent、完整周期管理与有限自主推进仍在建设中。保留能力边界、项目更新及两个学习入口。

中文版首页内容与局部样式维护在 `src/components/ChineseHome.astro`，由语言路由按中文条件渲染；英文内容和共享首页样式保持原有版本。任务 DAG、文档分层、测试分级与执行接入等细节由产品页和项目更新承载。

### 3.1 产品页

保留 `/<locale>/product/` 路由和 Starlight 阅读布局。页面依次说明产品定位、一个公共接口功能案例的目标工作流、Roadmap 与 DAG、测试验收、四层文档、协作职责，以及当前阶段与后续方向。正文底部提供学习入口和主仓库来源、愿景、验收及执行方案链接。

首页负责快速建立产品认知，产品页负责解释方法如何连接。能力说明以主仓库 README 和对应验收范围为依据。面向用户的主 Agent、完整周期管理、有限自主推进以及 Claude 执行接入不得写成当前已实现能力；当前接入按本地 Codex、本机 Orca 与远端 Orca 路径说明。中英文同步维护。

## 4. 技术架构

### 4.1 技术选型

| 层次 | 选型 | 职责 |
| --- | --- | --- |
| 网站框架 | Astro + TypeScript | 构建官网页面、内容列表和路由 |
| 文档框架 | Starlight | 提供教程和参考文档的文档布局、导航及搜索能力 |
| 内容格式 | Markdown + MDX | Markdown 用于常规写作；MDX 用于需要组件的内容 |
| 内容管理 | Git 仓库 + 内容元数据 | 管理内容、翻译、审查和历史版本 |
| 样式 | CSS 变量 + CSS | 建立统一的颜色、字体、间距和组件风格 |
| 搜索 | 静态站内搜索 | 搜索教程和参考文档；上线前验证中英文效果 |
| 发布 | 静态构建 + CDN | 提供官网和内容页面 |
| 自动化 | GitHub Actions | 执行构建与质量检查；正式发布通过 Wrangler Direct Upload 手动完成 |

官网自定义页面与文档页面同属一个站点，使用统一品牌、导航和双语规则。交互功能按需引入，初期不设独立后端、数据库或用户系统。

### 4.2 内容组织

网站内容按语言和用途组织，具体目录可在初始化时根据 Starlight 的配置方式调整。逻辑结构如下：

```text
content/
├── en/
│   ├── ai-engineering/
│   ├── steerline/
│   ├── about/
│   └── updates/
└── zh-cn/
    ├── ai-engineering/
    ├── steerline/
    ├── about/
    └── updates/
```

使用稳定的 **content ID** 关联不同语言版本。ID 表示同一篇逻辑内容，不依赖文件名是否相同。

建议内容元数据包含：

- 内容 ID、标题、摘要和语言。
- 所属栏目、排序或学习路径信息。
- 发布日期和最后更新日期。
- 翻译状态及对应原文版本。
- SteerLine 操作内容的适用版本和最后验证日期。

具体字段及必填规则在实施时定义为内容 schema，并通过构建检查。

### 4.3 质量与发布检查

合并前至少检查：

- 网站构建和内容元数据校验通过。
- 内部链接、图片和语言切换链接有效。
- 新增或修改的 SteerLine 操作步骤与标注版本一致。
- 中英文导航、搜索和移动端阅读体验正常。
- 页面具备基础可访问性，例如清晰的标题层级、键盘导航和图片替代文本。

教程发布前应检查命令和操作步骤是否可复现；不能验证的内容需要明确说明其状态。

## 5. 中英文架构与发布流程

### 5.1 默认语言与路由

**英文是网站默认语言；中文是日常内容的首写语言。**

| 语言 | 路径示例 |
| --- | --- |
| 默认入口 | `/` 跳转到 `/en/` |
| 英文首页 | `/en/` |
| 中文首页 | `/zh-cn/` |
| 英文 AI 教程 | `/en/ai-engineering/` |
| 中文 AI 教程 | `/zh-cn/ai-engineering/` |
| 英文 学习 SteerLine | `/en/steerline/` |
| 中文 学习 SteerLine | `/zh-cn/steerline/` |

根路径固定进入英文首页，不根据浏览器语言强制改变访问语言。访客可主动切换语言，也可直接访问任意语言地址。

### 5.2 语言切换

- 对应语言版本存在时，切换到同一内容的另一语言版本。
- 对应翻译不存在时，明确告知用户，并提供已有语言的原文链接。
- 不静默跳回首页，也不把中文正文作为英文页面展示。
- 已发布的翻译如果落后于原文，应显示清楚的状态提示。

页面应为搜索引擎提供正确的语言信息和对应版本关系，包括语言专属标题、描述、站点地图及 `hreflang`。

### 5.3 内容发布流程

```text
中文撰写 → 中文事实、技术与结构审查 → 中文发布
    → 英文翻译与编辑 → 英文术语、事实和可读性检查 → 英文发布并关联中文
```

中文可以先于英文发布。英文未准备好时，不创建不完整的英文正文页面；对应内容应能提示用户目前只有中文版本。

中文文章发生实质修改后：

1. 标记英文版本需要同步。
2. 在已有英文页面上提示其可能落后于中文原文。
3. 完成英文更新及审查后，记录同步状态。

具体哪些修改属于实质修改，由内容维护规则界定；会影响结论、操作步骤或产品行为的修改应包含在内。

### 5.4 术语管理

维护中英文术语表，统一 Spec、Roadmap、DAG、Git worktree、Task、review、verification 等产品和工程术语。术语表记录英文标准写法、中文译法及必要的使用说明；产品界面、教程和参考文档应尽量保持一致。

## 6. 内容来源与维护责任

- [SteerLine 主仓库](https://github.com/erranliu/SteerLine)是产品实现、内部设计和项目状态的重要来源。
- 官网仓库维护面向读者的产品介绍、教程、参考文档及其翻译。
- 引用主仓库内容时链接对应来源，避免无维护责任地整份复制内部文档。
- 产品命令、界面或工作流程变化时，检查受影响的教程和参考文档。
- 教程中的示例、截图和操作步骤记录适用版本；保留旧版本内容时清楚标明适用范围。
- 学习 AI 开发中的通用观点可以独立维护；涉及 SteerLine 具体行为时仍需与产品当前状态核对。

## 7. 分阶段建设

### 第一阶段：建立基础

- 初始化 Astro、Starlight、双语路由和统一视觉样式。
- 完成首页、产品概览和两个教程入口。
- 建立中英文内容 schema、语言切换、术语表和基本发布检查。
- 发布首批内容：Spec、worktree、AI 的能力限制、人在大型项目中的角色；以及 SteerLine 核心理念、Roadmap 和 DAG。
- 对尚未稳定的产品能力明确标注状态。

### 第二阶段：完善学习路径

- 补充可复现的 SteerLine 入门教程和完整案例。
- 建立教程内的前后篇导航、内容关联和搜索体验。
- 补充安装、配置、命令、排错等参考文档。
- 完善翻译同步检查与产品文档更新流程。

### 第三阶段：根据实际需求扩展

根据内容规模和维护需求，评估可视化内容管理、版本化文档、课程进度或其他动态功能；是否引入后端以实际使用需求为准。
