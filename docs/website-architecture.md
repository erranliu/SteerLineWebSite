# SteerLine 官网架构方案

本文记录目前确认的网站定位、技术栈、页面结构和双语内容发布流程，作为后续设计与开发的依据。页面路径和目录为建议结构，实施时可根据框架约束调整，但应保留本文确定的内容边界和语言规则。

## 1. 网站定位

官网承担三个职责：

1. **产品入口**：介绍 SteerLine 的定位、核心理念、工作方式和项目状态。
2. **知识传播**：发布面向严肃 AI 软件工程的通用开发教程。
3. **产品学习与参考**：提供 SteerLine 使用教程，以及准确、可检索的功能和配置文档。

网站面向希望使用 AI 开发真实软件的个人开发者、技术负责人和团队，既帮助初次接触者理解方法，也支持使用者在实际项目中查找操作和参考信息。

SteerLine 当前尚未发布。官网应区分已实现并验证的能力与计划中的能力，并随产品进展更新项目状态。

## 2. 信息架构

### 2.1 主导航

| 英文 | 中文 | 用途 |
| --- | --- | --- |
| Product | 产品 | 产品定位、理念、工作方式和状态 |
| AI Engineering | AI 开发教程 | 不依赖特定产品的 AI 软件工程方法 |
| SteerLine Guide | SteerLine 教程 | SteerLine 的理念、操作和实践案例 |
| Reference | 参考文档 | 功能、配置、命令和排错参考 |
| Updates | 项目更新 | 开发进展和发布记录 |
| GitHub | GitHub | 进入 SteerLine 开源仓库 |

导航提供中英文切换入口。关于页面可放在页脚，并从产品页链接。

### 2.2 页面结构

中英文使用相同的信息架构和内容分类。下方路径省略语言前缀：

```text
/
├── product/                     产品
│   ├── overview/                产品概览
│   ├── how-it-works/            核心理念与工作方式
│   └── roadmap/                 项目状态与路线图
├── ai-engineering/              AI 开发教程
│   ├── getting-started/         AI 软件工程入门
│   ├── specs/                   需求与 Spec
│   ├── planning/                规划与任务拆分
│   ├── collaboration/           多任务协作与 Git worktree
│   ├── ai-limitations/          AI 的能力与局限
│   ├── human-role/              大型项目中人的角色
│   └── verification/            验证、审查与交付
├── steerline/                   SteerLine 教程
│   ├── getting-started/         入门与准备
│   ├── concepts/                核心理念
│   │   ├── roadmap/             Roadmap 驱动开发
│   │   ├── dag/                 DAG 与任务依赖
│   │   └── collaboration/       人、AI 与工具的分工
│   ├── roadmap-guide/           创建和维护 Roadmap
│   ├── task-execution/          任务执行与状态管理
│   ├── review-and-delivery/     审查、验证与合并
│   └── examples/                完整项目案例
├── docs/                        参考文档
│   ├── installation/            安装与配置

│   ├── reference/               命令与配置项

├── updates/                     项目更新与发布记录
└── about/                       愿景、贡献与联系
```

具体文章随产品成熟度逐步增加，第一版不必创建空页面。

### 2.3 内容边界

| 内容区 | 回答的问题 | 内容特征 |
| --- | --- | --- |
| AI 开发教程 | 为什么这样做？通用方法是什么？ | 以软件工程问题和方法为中心，可独立于 SteerLine 阅读 |
| SteerLine 教程 | 如何用 SteerLine 实践？产品为什么这样设计？ | 解释产品理念、完整操作流程和实践案例 |
| 参考文档 | 某个功能、命令或配置具体如何工作？ | 准确、完整、易检索，随产品版本维护 |

例如，AI 开发教程解释为什么使用 worktree 隔离并行任务；SteerLine 教程解释如何在 SteerLine 工作流中处理相关任务；参考文档记录具体配置和行为。三类内容应互相链接，避免重复维护同一项精确配置或命令说明。

## 3. 首页结构

1. **产品定位**：说明 SteerLine 面向的 AI 软件工程场景，以及人如何掌握目标和关键决策。
2. **问题与方法**：解释规划、任务依赖、执行、验证和审查如何衔接。
3. **工作流程**：展示从目标与规格，到 Roadmap、任务执行、验证和合并的过程，标明人的决策节点。
4. **核心理念与产品能力**：介绍 Roadmap、DAG 驱动任务和人机协作，并标明能力状态。
5. **两条教程入口**：分别进入 AI 开发教程和 SteerLine 教程。
6. **项目状态与开源参与**：链接项目更新、GitHub 和贡献方式。

首页和产品页的能力描述以已验证的产品状态为依据；规划中的功能明确标注。

## 4. 技术架构

### 4.1 技术选型

| 层次 | 选型 | 职责 |
| --- | --- | --- |
| 网站框架 | Astro + TypeScript | 构建官网页面、内容列表和路由 |
| 文档框架 | Starlight | 提供教程和参考文档的文档布局、导航及搜索能力 |
| 内容格式 | Markdown + MDX | Markdown 用于常规写作；MDX 用于需要组件的内容 |
| 内容管理 | Git 仓库 + 内容元数据 | 管理内容、翻译、审查和历史版本 |
| 样式 | CSS 变量 + CSS | 建立统一的颜色、字体、间距和组件风格 |
| 搜索 | 静态站内搜索 | 搜索教程和参考文档；上线前验证中英文效果 |
| 发布 | 静态构建 + CDN | 提供官网和内容页面 |
| 自动化 | GitHub Actions | 执行构建与质量检查，并在合并后发布 |

官网自定义页面与文档页面同属一个站点，使用统一品牌、导航和双语规则。交互功能按需引入，初期不设独立后端、数据库或用户系统。

### 4.2 内容组织

网站内容按语言和用途组织，具体目录可在初始化时根据 Starlight 的配置方式调整。逻辑结构如下：

```text
content/
├── en/
│   ├── ai-engineering/
│   ├── steerline/
│   ├── docs/
│   └── updates/
└── zh-cn/
    ├── ai-engineering/
    ├── steerline/
    ├── docs/
    └── updates/
```

使用稳定的 **content ID** 关联不同语言版本。ID 表示同一篇逻辑内容，不依赖文件名是否相同。

建议内容元数据包含：

- 内容 ID、标题、摘要和语言。
- 所属栏目、排序或学习路径信息。
- 发布日期和最后更新日期。
- 翻译状态及对应原文版本。
- SteerLine 操作内容的适用版本和最后验证日期。

具体字段及必填规则在实施时定义为内容 schema，并通过构建检查。

### 4.3 质量与发布检查

合并前至少检查：

- 网站构建和内容元数据校验通过。
- 内部链接、图片和语言切换链接有效。
- 新增或修改的 SteerLine 操作步骤与标注版本一致。
- 中英文导航、搜索和移动端阅读体验正常。
- 页面具备基础可访问性，例如清晰的标题层级、键盘导航和图片替代文本。

教程发布前应检查命令和操作步骤是否可复现；不能验证的内容需要明确说明其状态。

## 5. 中英文架构与发布流程

### 5.1 默认语言与路由

**英文是网站默认语言；中文是日常内容的首写语言。**

| 语言 | 路径示例 |
| --- | --- |
| 默认入口 | `/` 跳转到 `/en/` |
| 英文首页 | `/en/` |
| 中文首页 | `/zh-cn/` |
| 英文 AI 教程 | `/en/ai-engineering/` |
| 中文 AI 教程 | `/zh-cn/ai-engineering/` |
| 英文 SteerLine 教程 | `/en/steerline/` |
| 中文 SteerLine 教程 | `/zh-cn/steerline/` |

根路径固定进入英文首页，不根据浏览器语言强制改变访问语言。访客可主动切换语言，也可直接访问任意语言地址。

### 5.2 语言切换

- 对应语言版本存在时，切换到同一内容的另一语言版本。
- 对应翻译不存在时，明确告知用户，并提供已有语言的原文链接。
- 不静默跳回首页，也不把中文正文作为英文页面展示。
- 已发布的翻译如果落后于原文，应显示清楚的状态提示。

页面应为搜索引擎提供正确的语言信息和对应版本关系，包括语言专属标题、描述、站点地图及 `hreflang`。

### 5.3 内容发布流程

```text
中文撰写 → 中文事实、技术与结构审查 → 中文发布
    → 英文翻译与编辑 → 英文术语、事实和可读性检查 → 英文发布并关联中文
```

中文可以先于英文发布。英文未准备好时，不创建不完整的英文正文页面；对应内容应能提示用户目前只有中文版本。

中文文章发生实质修改后：

1. 标记英文版本需要同步。
2. 在已有英文页面上提示其可能落后于中文原文。
3. 完成英文更新及审查后，记录同步状态。

具体哪些修改属于实质修改，由内容维护规则界定；会影响结论、操作步骤或产品行为的修改应包含在内。

### 5.4 术语管理

维护中英文术语表，统一 Spec、Roadmap、DAG、Git worktree、Task、review、verification 等产品和工程术语。术语表记录英文标准写法、中文译法及必要的使用说明；产品界面、教程和参考文档应尽量保持一致。

## 6. 内容来源与维护责任

- [SteerLine 主仓库](https://github.com/erranliu/SteerLine)是产品实现、内部设计和项目状态的重要来源。
- 官网仓库维护面向读者的产品介绍、教程、参考文档及其翻译。
- 引用主仓库内容时链接对应来源，避免无维护责任地整份复制内部文档。
- 产品命令、界面或工作流程变化时，检查受影响的教程和参考文档。
- 教程中的示例、截图和操作步骤记录适用版本；保留旧版本内容时清楚标明适用范围。
- AI 开发教程中的通用观点可以独立维护；涉及 SteerLine 具体行为时仍需与产品当前状态核对。

## 7. 分阶段建设

### 第一阶段：建立基础

- 初始化 Astro、Starlight、双语路由和统一视觉样式。
- 完成首页、产品概览和两个教程入口。
- 建立中英文内容 schema、语言切换、术语表和基本发布检查。
- 发布首批内容：Spec、worktree、AI 的能力限制、人在大型项目中的角色；以及 SteerLine 核心理念、Roadmap 和 DAG。
- 对尚未稳定的产品能力明确标注状态。

### 第二阶段：完善学习路径

- 补充可复现的 SteerLine 入门教程和完整案例。
- 建立教程内的前后篇导航、内容关联和搜索体验。
- 补充安装、配置、命令、排错等参考文档。
- 完善翻译同步检查与产品文档更新流程。

### 第三阶段：根据实际需求扩展

根据内容规模和维护需求，评估可视化内容管理、版本化文档、课程进度或其他动态功能；是否引入后端以实际使用需求为准。
